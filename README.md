# TazaMap

Карта мусора и уборок Петропавловска. Жители отмечают загрязнённые места, видят их на карте, организуют уборки и получают баллы, которые меняются на скидки у местных партнёров.

**Живой сервис:** https://taza-map.vercel.app

Проект работает в продакшене. Разработан одним человеком: бэкенд, база данных, деплой.

---

## Зачем

В городе много стихийных свалок, но нет места, где видно, где именно они находятся и убрал ли их кто-нибудь. Жалобы расходятся по чатам и теряются. TazaMap связывает три вещи: точку на карте, её фотографию и уборку, — и вознаграждает участие.

## Возможности

- Регистрация и вход по номеру телефона с хешированием пароля
- JWT-аутентификация, защита эндпоинтов через зависимости FastAPI
- Роли пользователя и администратора
- Создание точек на карте с фотографией, координатами и уровнем загрязнения
- Привязка точки к автору
- Уборки, привязанные к точкам
- Коды ошибок вместо текстовых сообщений — интерфейс переводит их на три языка

---

## Архитектура

```
Клиент (React + TypeScript, Vercel)
        |  REST, JSON, JWT в заголовке Authorization
        v
API (FastAPI, Render)
        |  SQLAlchemy 2.0
        v
База данных (PostgreSQL, Neon)
```

Фронтенд и бэкенд развёрнуты независимо и общаются по REST с настроенным CORS. Секреты и строка подключения к базе хранятся только в переменных окружения и никогда не попадают в репозиторий.


## Запуск локально

### Бэкенд

```bash
cd backend
python -m venv .venv
.venv\Scripts\activate        # Windows
source .venv/bin/activate     # macOS и Linux
pip install -r requirements.txt
uvicorn main:app --reload
```

API поднимется на `http://127.0.0.1:8000`, интерактивная документация — на `http://127.0.0.1:8000/docs`.

### Переменные окружения

Создайте файл `backend/.env` по образцу:

```env
DATABASE_URL=postgresql://user:password@host/dbname
SECRET_KEY=любая_длинная_случайная_строка
```

`.env` добавлен в `.gitignore` и в репозиторий не попадает.

### Фронтенд

```bash
cd frontend
npm install
npm run dev
```

## Тесты

```bash
cd backend
pytest -v
```

23 теста: регистрация, вход, доступ к защищённым эндпоинтам. Тесты идут на отдельной базе и не трогают рабочие данные.

Что проверяется:
- валидация входных данных — формат телефона, длина имени и пароля
- занятый номер телефона
- неверные учётные данные при входе
- создание точки без токена, с испорченным токеном и с действительным токеном
- что автор точки записывается правильно

## Решения и почему

**Коды ошибок вместо текста.** API возвращает `phone_taken`, `invalid_credentials`, `not_authenticated`. Интерфейс переведён на три языка, и переводить сообщения должен клиент, а не сервер.

**argon2, а не bcrypt.** У bcrypt есть ограничение в 72 байта на длину пароля: всё, что длиннее, молча обрезается. argon2 такого поведения не имеет.

**Флаги функций.** Отметка точек и уборки включаются одной настройкой. Зимой уборок нет, а модерация ещё не готова — вместо выключенного сервиса интерфейс показывает «скоро».

**Модерация до открытия отметок.** Фотографию загружает кто угодно, значит возможны чужие дворы и случайные люди в кадре. Отметка точек закрыта, пока новые точки не начнут проходить проверку администратором.

**Баллы после подтверждения номера.** Иначе один человек заведёт сколько угодно аккаунтов и начислит себе баллы сам.
